## Этап A — эмпирический анализ формата 🔬
*(инструментальная пауза перед Stage 3: поведение формата исследовано
на живом декодере FFmpeg и 218 эталонных битстримах NTT TestEnc;
скрипты и данные — `python/analysis/`, сводка — docs/ENCODE_PIPELINE.md)*

### A.1 — Зондирование декодера FFmpeg синтетикой (E0–E7) ✅
- python/analysis/exp_probe.py: генерация синтетических VQF (полный
  контроль над каждым полем кадра) → декодирование системным ffmpeg.
- E0: priming = 2 кадра (discarded_packets), латентность вход→выход
  k → k+2; ffprobe подтверждает параметры.
- E1: «нулевой» кадр = кодвектор #0 всех книг — базовый сигнал,
  нулевые индексы НЕ означают тишину.
- E2/E2b: развёртки p_coef × g_coef — PPC-геометрия (периоды, mulaw-гейн).
- E3: bark-полосы покрывают спектр до ~22.05 кГц (границы полос
  через отношение спектров соседних вариантов).
- E4: lpc_idx1 → крупномасштабная спектральная огибающая.
- E5: карта распространения битовых ошибок: main VQ / wtype / PPC
  локализованы в выходных кадрах k−2, k−1; LSP-ошибка из-за
  MA-предсказания дополнительно задевает кадр k.
- E6: wtype-последовательности во времени (оконная структура).
- E7: metadata-чанки; обрезка DATA отдаёт floor(n_full) кадров;
  wtype=8 отвергается декодером (в NTT-потоках не встречается).
- Результаты: python/analysis/results/vqf_probe_results.json.

### A.2 — Карта влияния полей (микро-флипы битов) ✅
- Серия dbg5–dbg9: переворот одного бита конкретного поля → диф
  декодированного PCM по кадрам. Уточнение карты E5 до уровня полей.
- Вывод учтён в ARCHITECTURE.md §6 (порядок полей) и §9.

### A.3 — Парсер эталонных битстримов NTT ✅
- python/reference/vqflib.py: BitReader, parse_frame (все поля по §6
  ARCHITECTURE.md), parse_vqf, write_vqf, битовый бюджет.
- Найден и устранён собственный баг data_off (DATA-чанк без len) —
  после фикса **218/218** эталонных .vqf NTT TestEnc парсятся на 100%
  (хвосты 0–4 бита на файл).

### A.4 — Массовая статистика реальных потоков ✅
- python/analysis/real_stats.py: 218 файлов, 5 наборов, 9 режимов:
  wtype-гистограммы; gain/sub_gain; PPC-активность; bark_use_hist

- Ключевые факты: стартовая последовательность wtype энкодера NTT —

  (decor_stereo: g_coef=127, период ≈200 Гц); тишина → все LONG,
  gain=0; silence.vqf не содержит стартовой скобки.
- Результаты: ntt_real_stats.json (вне репо, регенерируется скриптом).

### A.5 — Битовый бюджет всех режимов ✅

## Этап 5.0 — глубокий разбор энкодера NTT ✅
*(запрошен до старта Stage 5: «как происходит кодирование сигнала

### 5.0.1 — Бит-точный python-оракул ✅

- python/reference/synth_check.py: валидация против системного ffmpeg —
  **12 файлов NTT (моно/стерео, 4 режима, все ftype/wtype): corr =
  1.00000000, rel_err ≤ 3·10⁻⁶**.
- В ходе валидации найдены/исправлены 4 собственных бага порта
  (паддинг-биты pack_frames; prev_buf канала 1 по обновлённой позиции;
  floor-vs-trunc отрицательного деления; плоские 2D-таблицы tab7..tab12) —
  задокументированы как обязательные к учёту в C++ (ENCODE_PIPELINE.md §1).

### 5.0.2 — Калибровка MDCT-мишени (E1) ✅
- Мишень кадра k = MDCT входа с синусным окном 2B, смещение
  **off = (k−2)·size** (2 кадра pre-roll, компенсируются discard-пакетами
  декодера), масштаб c = 2¹⁶/√(norm·B).
- Наклон 581/1029 против теории 1024/1448 — разница = усушка
  конъюгатного VQ; симуляция α(σ): 0.18…0.77, измерено 0.57/0.71.

### 5.0.3 — Послойная декомпозиция (E2) и PPC-гребёнка (E2b) ✅
- Послойные корреляции 0.80–0.91 (VQ·Bark·gain+PPC vs мишень).
- PPC = гармоническая гребёнка, f0 ∈ [100, 600] Гц одинаково для всех
  режимов; при f0 < 100 Гц кодируется ближайшая гармоника сверху
  (52→104, 62→124, 74→148 Гц); ширина пика ∝ периоду.

### 5.0.4 — Грамматика окон (E3) ✅
- атака → [L1, S2×n, L3], стационар → L0, тишина → L0 без стартовой
  скобки; wtype 0/1/6 синтезируются идентично; длина S-серии растёт
  с резкостью атак (7→26 кадров у clicks).

### 5.0.5 — Документ ✅
- **docs/ENCODE_PIPELINE.md** — главный артефакт анализа: трёхслойная
  модель X̂ = (VQ·Bark·gain + PPC)·LPC, каждый слой с бюджетом и

## Этап R17 — стереогребёнка PPC: общий период пары (2026-10-24)

Контекст: decor_stereo — единственное отставание от NTT (7.27 vs их
11.17 дБ; их метрика асимметрична L=11.17/R=4.62, честная на паритете
7.15). Разбор NTT: гребёнки каналов в ~83% кадров имеют один период
(corr 0.78) — NTT кодирует СТЕРЕО ОБЩЕЙ гребёнкой (формат это позволяет:
period-поле поканальное, но поиск у NTT сходится к одному p; тон в
L-домене c0+c1 виден в обоих каналах одновременно — M/S-геометрия).

Сделано (src/encoder.rs):
- `ppc_search_stereo`: период ОДИН на пару — максимум покрытия в
  L-домене (c0+c1); гейны поканальные (`ppc_gain_scan` — рефакторинг
  общего скана му-лог грида: грубый проход каждые 4 индекса параллельно
  + уточнение ±3); приёмка ПАРЫ в encode_frame: L-домен обязан чисто
  изымать ≥ ε энергии (keep_l), R-домен — страховка от сильного вреда
  (keep_r ≥ −ε); пара живёт или умирает целиком.
- Поканальный NOCOVER-гейт: если общий период не покрывает канал
  (тон в L, канал — шум: music_like), гребёнка канала аппроксимировала
  бы шум (entries = flat[ch]·c/g ≠ 0) и портила W[ch] — такой канал
  идёт без гребёнки (sel=None), как в поканальном поиске. Первый вариант
  R17 без гейта терял music_like −1.22 дБ — гейт вернул побитово.
- `cover_of_bins` — выделенный хелпер покрытия (±1 бин, max) с
  замыканием домена (поканальный / L).
- `TEQUILA_PPC_FULLSCAN` — исследовательский полный перебор периодов
  по быстрой L-оценке (`ppc_eval_l`: общий g=127, VQ+decode, ошибка
  в L-домене на пиках): показывает потолок выбора периода — покрытие
  (p≈401–408 на decor) не оптимален по точной оценке (лучшие 178–339),
  но точный скан стоит VQ+decode на каждый из 512 периодов — оставлен
  флагом, в прод не включён.
- `examples/perm_test.rs` — диагностика интерлива совместной PPC-формы:
  перестановка ложит каналы bark-порядком (блоки по 7–13 позиций),
  НЕ парами (2m, 2m+1) — гипотеза «соседние позиции = один бин двух

## Этап R16 — рабочая точка PPC: скан грида гейна + масштаб цели (2026-10-24)

Разбор decor_stereo (7.0 vs NTT 11.2) вскрыл три вещи:

1. **Асимметрия L/R у NTT — не качество, а перекладывание ошибки.**
   NTT: L=11.17 дБ, R=4.62 дБ; мы: L=7.27, R=5.61. Честная метрика
   обоих каналов (L+R): NTT 7.15 vs наши ~6.9 — паритет. Бенчмарк
   измеряет только ch0: NTT антикоррелирует ошибки каналов
   (corr −0.55), уменьшая ошибку L за счёт R.
2. **Механизм NTT — общая PPC-гребёнка.** Постфактум-удаление PPC из
   декода NTT: L 11.17 → 1.12 дБ, R не меняется — гребёнка несёт ~83%
   энергии L. Комбы каналов почти идентичны (corr 0.78, |p0|≈|p1|):
   складываются в L, вычитаются в R. На music_like (L≈R) у NTT PPC
   включён только в c0 — правило адаптивное.
3. **Наш PPC-путь ломался на рабочей точке, а не на поиске:**
   - грид pgain му-логарифмический (0.0003…3.05, шаг у верхушки ×4.8),
     σ-эвристика g_des = amp/σ ≈ 10–17 ВНЕ грида → насыщение в 127
     при ЛЮБОМ громком сигнале;
   - цель формы amp/gain ≈ 3.5σ_shape недостижима для пары кодбуков
     (естественная величина ≈ √2·σ): поиск берёт максимальные по норме
     строки с чужим направлением, гребёнка «перелетает» (err > base),
     приёмка отключает канал (decor: c1 убит в 21% кадров);
   - p=0 в гриде периодов зарезервирован декодером как «PPC выкл»;
     на multitone поиск выбирал ровно его (cover 22–58%!) — гребёнка
     терялась. Проверено исключение p=0 из перебора: multitone
     получает гребёнку, но она ВРЕДИТ (7.21 → 5.95) — откачено;
     вопрос совместного качества формы остаётся открытым.

Реализовано (commit):
- `ppc_search_ch`: полный скан грида гейна вместо окна ±6 вокруг
  насыщенного центра — грубый проход каждые 4 индекса + уточнение ±3,
  оценка — фактическая ошибка на пиках при кодировании формы.
- Масштаб цели формы: c = min(1, PPC_SHAPE_KAPPA·σ·gain/amp),
  PPC_SHAPE_KAPPA = 1.5 — частичная гребёнка α·flat всё равно изымает
  (2α−α²) энергии пиков (α=0.4 → 64%), а направление кодируется точно.
- Диагностика: TEQUILA_PPC_DEBUG (FOUND/KILL/NOCOVER по кадрам).

Попутно найден баг python-оракула: на патологических LSP (близкие
корни) env взрывается до 1e9 (кадр 20 decor NTT) — наш Rust-декодер
совпадает с ffmpeg (diff 3e-5), python — нет. Послойный анализ NTT-
файлов впредь только через Rust-декодер.

Результаты (корпус 38 файлов): средний seg-SNR **19.95 дБ** (R15:
19.71, NTT: 10.08). sine_1k 49.5 → 55.6 (+6.0), am_tone +2.7,

## Этап R15 — взвешенный VQ-поиск: метрика в домене выхода (2026-10-24)

Диагноз clicks (4.7 vs NTT 24.1 дБ, послойный разбор через дамп мишеней
`TEQUILA_DUMP_TARGETS`):
- Импульсные сигналы: энергия кадра в 1–2 подкадрах из 16; bark-масштаб
  «пустых» полос ≈ 4e-4. Мишень R = X/scale там, где X ≈ 0, — ноль, но
  перестановка interleave смешивает бины разных подкадров в каждой
  дивизии (14 бинов из 14 разных подкадров).
- Невзвешенный NN минимизирует Σ ΔV² — тратит бюджет ошибки на бины,
  которые декодер умножает на ~0: искажается совпадение на значимых
  бинах (наши |V|/|R| = 1.19, corr 0.86 против NTT 0.99, corr 0.99).
- Решающий тест: NN на мишени NTT даёт eff 0.28 против фактических
  0.07 — значит NTT ищет не в домене R, а взвешенно. Взвешенный поиск
  min Σ w_t·ΔV_t², w = scale² = (env·st·g)² — это в точности ошибка
  реконструкции кадра: на нашем масштабе eff 0.398 → 0.025 (15.6×),
  на масштабе NTT 0.072 → 0.022.

Реализация:
- `CbPairCache::search_w` — точный взвешенный NN: нормировка весов,
  активное множество (w ≥ 1e-4·max — исключается из всех сумм),
  отсев строк Коши–Буняковским (|cross| ≤ √(n0w·n1w)), кросс-члены —
  непрерывный FMA по транспонированной активной подматрице cb1
  (авто-векторизация).
- `quant_vq_main_w` — маршрутизация по дивизиям: почти равномерные
  веса (max ≤ 8·min > 0) → кэшированный невзвешенный поиск (битстрим
  стационарных кадров не меняется), контрастные → взвешенный.
- `encoder.rs`: веса w = (env·st·g)² строятся в том же цикле, что и
  VQ-цель R = W/(st·g); дамп мишеней по TEQUILA_DUMP_TARGETS для
  послойной диагностики (формат: u32×4 заголовок + f64 LE).

Результаты (корпус 38 файлов, seg-SNR против входа):
- Средний уровень: **19.71 дБ vs NTT 10.08** (R14: 12.08).
- clicks 30.93 (NTT 24.06), pink 15.62 (14.10), music_like 55.73
  (24.00), sweep 8m8 40.22 (15.86), 16m16 45.19 (20.78) — регрессий
  нет ни на одном файле корпуса.
- Скорость: clicks 2.90 → 1.52 с, pink 2.76 → 1.88 с (транспонирование
  подматрицы), 5–6.6× realtime на файле 10 с (R14: 8×; качество
  дороже). Профиль: vq = 1.5–2.7 с — следующая цель SIMD (avx2/fma
  через runtime-dispatch).
- 61/61 тестов зелёные.

## Этап R12 — четыре исправления конвейера (2026-10-24)

Контекст: ревизия конвейера выявила четыре системных дефекта качества.

Сделано:

1. **LPC по знаковым коэффициентам вместо |X|** (`analysis.rs`):
   `lpc_target_spectrum` получал знаковые X и сглаживал их без abs —
   огибающая схлопывалась к шуму (~25 дБ вместо ~70 дБ), а bark-слой
   имеет лишь ~10 дБ динамики (st ≥ 1.1) — всю глубокую форму обязан
   нести LPC. На материалах с ограниченной полосой выход был на 40–65 дБ
   выше цели в «пустых» зонах. Исправление — `sp[k].abs()`. Тест
   `lpc_envelope_covers_deep_spectral_shape`: провал полоса/стоп ≥ 40 дБ.
2. **Знаки в конъюгатном VQ** (`quantize.rs::quant_vq_div`): выбирались
   независимо по знаку скалярного произведения (остаток содержит
   cross-член 2·s0·s1·(a·b) — оптимум может требовать (+,+) при
   dot(v,a) < 0), и предполагались там, где знакового бита нет (при
   6-битном индексе декодер всегда читает +1; в 44_48 — 3 дивизии из
   148, в 8m8 — 10 из 31). Исправление: совместный перебор 4 комбинаций
   только где знаки кодируются. Тест `vq_div_signs_joint_and_encodable`
   — глобальный минимум против brute-force по всем кодируемым парам.
3. **Геометрия анализа SHORT/MEDIUM** (`encoder.rs::analysis_targets` +
   `dsp.rs::mdct_analysis_compact`): декодер синтезирует SHORT окнами с
   короткими наклонами (схема Эдлера, правый наклон блока задаётся
   левым наклоном следующего), блоки сдвинуты на (size−b)/2, центры
   первых наклонов на сетке c_k = (k−2)·size + size/2 — энкодер же
   анализировал полным синусным окном 2b без сдвига (нарушение TDAC,
   отрицательный SNR на 35–50% кадров). Реализован точный адъюнкт
   синтеза: Ō-буфер желаемых значений curr (линейная часть + фолд через
   бабочку кадра k+1), по подкадрам (i) бабочка (ii) плоская часть
   (iii) P-часть следующей бабочки, X = −c·mdct_analysis_compact(y).
   Тесты: `analysis_long_matches_mdct_fwd` (для LONG адъюнкт == c·mdct_fwd,
   масштаб ровно 1.0, max_rel ≤ 2·10⁻⁹ — калибровка E1 сохранена) и
   `analysis_synthesis_pr` — **PR-SNR 252–256 дБ при масштабе ровно
   1.000000000** на всех допустимых последовательностях окон (все L0,
   стартовая скобка, атака в середине, плотные клики, S2-серия в конце).
4. **decide_wtypes** (`encoder.rs`): детектор смотрел на [k·size, …),
   а кадр k покрывает [c_k, c_k+size) — рассинхрон ~1.5 кадра; слипшиеся
   скобки затирали L3 единицей → запрещённый переход S→L1 (длинное окно
   после короткого). Исправлено: покрытие [c_k, c_k+size) и L1 только
   на месте L0. Тест `wtypes_grammar` расширен проверкой запрета S→L1.

Результат E2E (бенчмарк против NTT TestEnc, 38 файлов): **tequila

## Этап R14 — производительность: SIMD-FFT, кэши, отсев (2026-10-24)

Контекст: энкодер был 0.42× realtime (10 с стерео 44s96 — 23.6 с):
наивные O(B²) MDCT/IMDCT с inline cos (B до 2048, таблица 64 МБ),
пересчёт кросс-матриц кодбуков каждый кадр (~17 млн MAC/кадр),
гриды mulaw/геометрия PPC на каждом кадре, скан корней LSP по 44 sincos
на точку сетки.

Сделано:
- `src/dsp.rs`: все три преобразования (mdct_fwd / imdct_compact /
  mdct_analysis_compact) сведены к единому ядру `fft_mdct` — один
  комплексный FFT размера 4B (rustfft 6.4, MIT/Apache-2.0, SIMD внутри)
  с таблицей W4c[t] = exp(−i·t·π/(4B)); анализ — Z-заполнение с учётом
  переноса t через 4B (знак (−1)^q), синтез — транспонированная схема.
  Планы/твиддлы — OnceLock-кэш, scratch — thread-local. Наивные
  реализации сохранены как тестовый эталон (`naive`).
  Точность: против наива 4e-13 (B=2048), против python-оракула
  5.2e-12 (порог 1e-9). Таблица 64 МБ исчезла из рантайма.
- `src/quantize.rs`: `CbPairCache` — кэш пар кодбуков (f64-копии,
  нормы, кросс-матрицы cross[i][j] и cmax[i] по ключу (b0,b1,len),
  ≤4 комбинации на пару). Поиск: факторизация столбцовых членов по
  знакам, отсев строк нижней оценкой
  vv + nrm0[i] − 2|dot0[i]| + min_j(nrm1[j] − 2|dot1[j]|) − 2·cmax[i]
  (оптимальная пара не отсекается никогда), минимум по j — zip-итераторы
  без bounds-checks (векторизуемый min-reduce), индекс — вторым
  проходом только при улучшении. Гриды gain/sub_gain — OnceLock +
  nearest_index через partition_point (монотонные, семантика тай-брейков
  линейного перебора сохранена).
- `src/encoder.rs`: Encoder держит кэши VQ [S,M,L]+PPC, гриды PPC и
  σ на поток; геометрия пиков add_peak мемоизируется по периоду (было
  512 пересчётов на канал каждого LONG-кадра); StreamInfo копируется
  (Copy) для разведения заимствований. Инструментация стадий
  (TEQUILA_PROFILE=1).
- `src/analysis.rs`: корни P/Q — парная схема (экспоненты ±m:
  re = Σ Dc·cos mθ, im = Σ Ds·sin mθ) со сканом рекуррентными
  вращениями (ресинхронизация каждые 8 шагов; |v| < 1e-9·Σ|d| —
